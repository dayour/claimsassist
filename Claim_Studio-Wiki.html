Claim_Studio

Workers' Compensation Case Management

Claim_Studio is a workers' compensation case-management solution for distributed operations teams. It provides a single workspace to intake workplace incidents, automatically classify them, track case status and financial reserves, and analyze claim trends across regions — backed by a live Microsoft Dataverse table.

Power Apps Code App Model-driven App Dataverse React + Vite + TypeScript Live data

Architecture

The solution combines a code-first Power App for the day-to-day operator experience with a model-driven app for administrative record management, both reading and writing the same Dataverse table.

Live Data Connectivity

All screens render from a single shared claims collection loaded from Dataverse at startup and refreshed after writes. The data layer (src/lib/dataverse.ts) is the only module that talks to the connector.

Connector operations

The org URL is resolved at runtime via GetOrganizations (cached), so the organization-scoped operations bind to whatever environment the app runs in:

ActionOperationKey parameters
Load casesListRecordsWithOrganizationorganization, entityName=owcp_claims, prefer=include-annotations, $orderby=datereported desc
Create caseCreateRecordWithOrganizationorganization, entityName, item=<field map>, prefer=return=representation
Connection metadataGetOrganizationsmatched by URL → org friendly name

Result handling

  • Success is always checked — every call inspects IOperationResult.success; a failure throws with the connector error instead of being masked as an empty table.
  • Shape is validated — list responses must contain a value array.
  • Graceful fallback — outside the Power host (local dev) calls fail fast and the UI falls back to bundled seed data. A live connection with zero rows reads as “Dataverse (live · 0 rows),” not a fallback.
  • Timeouts — each call is raced against a 30-second timeout.

Portability — no hard-coded environment values

The application contains no hard-coded environment-specific values (no org URL, environment id, or tenant id baked into the build). At startup the data layer calls GetOrganizations on the bound connection and caches the resulting org URL; every Dataverse read/write and every deep link is built from that runtime value plus the host getContext(). The verified-clean built bundle ships with the solution, so the same artifact runs unchanged in any environment.

ValueHow it is obtained

Tenant id / userRuntime — getContext().user

The dev-only power.config.json still references the authoring environment/app id — that file is the pac code push target pointer used during development and is not included in the shipped solution bundle.

Claim_Studio Code App

The operator-facing application — a Power Apps Code App built with React, Vite and TypeScript, published with pac code push. Four screens are presented via a persistent left navigation rail.

Dashboard

Purpose. Executive overview of the full case portfolio with drill-through into a filtered Claims view.

KPI cards

  • Total Claims — count of all cases.
  • Open / Active — cases not Closed/Denied.
  • Total Reserve — sum of Reserve (USD).
  • AI Classified — % of cases with a classification.

Panels

  • Recent Claims — five most recently reported cases.
  • Status Breakdown — color-coded bars per status (click to filter).
  • Incident Type Distribution — bars per type, sorted by volume.
Every figure is computed live from the Dataverse collection and recomputes on refresh.

Claims

Purpose. Searchable, filterable register of all cases with a detail drawer.

  • Free-text search across claim number, claimant, incident type, department, adjuster.
  • Filters: Status, Region, Open/Active toggle, Classified-only (drill-through).
  • Refresh (↻) — reloads the canonical list from Dataverse.
  • View in Dataverse (⧉) — opens the owcp_claim grid in the Workers' Comp Cases model-driven app (via portable appname).
  • Detail drawer — full record + classification card; its own View in Dataverse opens that specific record.

Report Incident

Purpose. Structured intake of a new incident, auto-classified, that writes a new case to Dataverse.

  1. Preview Classification renders an Adaptive-Card-style preview of the record to be filed.
  2. File Claim builds the case, assigns the next claim number, classifies the narrative, and persists to Dataverse.
  3. The button is disabled until valid; a helper line states exactly why (e.g. “N more characters needed”).
  4. A success banner appears only after Dataverse confirms the write; the list reloads and the footer count increments.
  5. On failure an error banner shows the connector message — no false success.
Validated end-to-end: claim OWCP-2026-9002 was filed via the UI and confirmed in Dataverse with all choice labels resolved correctly.

Incident Classifier

Purpose. Interactive tool mirroring the Copilot Studio classification workflow — given a narrative it returns a category, severity and recommended action.

  • Free-text narrative with five built-in sample incidents.
  • Keyword rules score the narrative against incident categories; severity is escalated/de-escalated by injury descriptors; confidence scales with keyword density.
  • The same logic runs on intake in Report Incident, so filed cases arrive pre-classified.
The in-app classifier is a deterministic stand-in for a Copilot Studio prompt node. Swapping classifyIncident() for a live Copilot Studio / Dataverse call is the intended productionization path.

PDF Template Schema

Purpose. Claim PDFs generated by Copilot Studio / Power Automate should use the repository schema docs/claim-studio-pdf-template-schema.md. The schema defines the fillable text boxes, section order, related-record summaries, and child-record rows for notes, documents, appointments, and tasks.

  • The first page must contain Claim Overview, Claimant Details, and Incident Details; no mostly blank cover page.
  • All display text must use Region, even though the Dataverse logical column remains owcp_property.
  • Workspace documents are metadata rows in owcp_casedocuments with a link/location; generated PDFs should be attached or linked by the external workflow.
  • Appointments are rows in owcp_caseappointments; if an appointment creates a task, that task is a separate owcp_casetasks row linked to the same claim.

Deployment Guide

Deploy to a new tenant/environment with PAC and the Node validation/release gates.

Prerequisites

  • Power Platform CLI: winget install Microsoft.PowerPlatformCLI
  • System Customizer / System Administrator role in the target environment.
  • Files: ClaimStudio_managed.zip, ClaimStudio_unmanaged.zip, and scripts/release.mjs.

Run

npm run release:check
npm run release:export
node scripts/release.mjs --deploy

The release gate builds the Code App, validates the solution zip, uses PAC to add required Dataverse table components to OWCPStudio, exports from darbotlabs, imports to the target, and publishes.

Verified cross-environment: the solution was deployed from the authoring environment (darbotlabs) to a separate test environment and confirmed — table present, model-driven app present, form with all 18 fields, and 0 rows (clean). The upgrade path (re-deploy of a newer version) was also verified.

Post-deploy

  1. Confirm the Claim_Studio code app and Workers' Comp Cases app appear in make.powerapps.com.
  2. Share both apps and assign security roles.
  3. Open the model-driven app grid: {orgUrl}/main.aspx?appname=dystudio_wccases&pagetype=entitylist&etn=owcp_claim.
  4. First time the code app is played, confirm the Microsoft Dataverse connection when prompted.
  5. Begin filing incidents from the code app, or load seed data.
The code app resolves its Dataverse org at runtime (via GetOrganizations), so the same build works in any environment with no rebuild required and no environment values baked in.
